# SuperCon2026 提出プログラムの解法解説

## 1. 解法の概要

今回提出したプログラムは、単純に円盤を圧縮していくシミュレーションではない。

**複数の初期配置を並列探索し、有望な配置を選別した後、適応的な圧縮・二分探索・振動による局所解脱出を組み合わせて、面積分率を最大化するヒューリスティック最適化ソルバ**である。

主な技術は次のとおり。

- **Cell List**：円盤間の近傍探索を高速化
- **OpenMP**：円盤単位の計算を並列化
- **FIRE**：円盤の重なりを解消
- **MPI**：複数の初期条件を並列探索し、候補解を交換
- **適応圧縮**：圧縮幅を成功・失敗に応じて調整
- **二分探索**：ジャミング境界を精密に探索
- **局所解脱出**：膨張・振動・再圧縮によって配置を組み替える
- **時間予測制御**：制限時間内に有効な解を出力

全体として、物理モデルを利用した緩和を基礎に、マルチスタート・局所探索・境界探索・並列化を組み合わせたハイブリッド型の最適化アルゴリズムである。

## 2. 最適化問題の定式化

3000個の異なる直径を持つ円盤を、周期境界条件付きの正方形領域に配置する。

目的は、円盤同士を重ねず、初期配置からの平均移動距離を10以下に保ちながら、正方形の一辺の長さ \(L\) を最小化すること。

円盤全体の面積を

\[
A=\sum_{i=1}^{N}\frac{\pi d_i^2}{4}
\]

とすると、面積分率（充填率）は

\[
\phi=\frac{A}{L^2}
\]

となる。

面積 \(A\) は変わらないため、\(L\) を小さくすることと、面積分率 \(\phi\) を大きくすることは同値である。

したがって、実質的な目的は

\[
\boxed{\max \phi}
\]

である。

制約条件には次の安全余裕を設けている。

| 項目 | 公式の制約 | プログラムの設定 |
|---|---:|---:|
| 最大重なり | \(10^{-10}\) 未満 | `SAFE_OVERLAP = 2.0e-11` |
| 平均移動距離 | 10以下 | `DISP_LIMIT = 9.98` |

## 3. 基本となる物理モデル

このプログラムでは、円盤同士の重なりを反発力で解消する、物理シミュレーションに似た方法を使っている。

ただし、厳密な剛体の物理シミュレーションではなく、**重なりを罰する仮想的なポテンシャルを使った数値最適化**である。

### 3.1 円盤間の反発力

円盤 \(i,j\) の中心間距離を \(r_{ij}\)、接触する距離を

\[
a_{ij}=\frac{d_i+d_j}{2}
\]

とする。

重なり量は

\[
\delta_{ij}=\max(0,a_{ij}-r_{ij})
\]

である。

重なっていなければ \(\delta_{ij}=0\)、重なっていれば正の値になる。

コードでは、この重なり量から反発力を計算する。

\[
F_{ij}\propto \frac{\delta_{ij}}{a_{ij}^2}
\]

円盤同士が近づきすぎたときだけ力が働き、互いに離れる方向へ移動する。

さらに、重なりの大きさに応じたペナルティエネルギーも計算している。

### 3.2 Cell Listによる高速化

3000個の円盤について、すべての組み合わせを毎回調べると、

\[
\frac{3000\times2999}{2}\approx450万
\]

組の計算が必要になる。

そこで、領域を格子状に分割し、近傍のセルに存在する円盤だけを調べる **Cell List** を利用している。

各円盤について周囲の3×3セルを調べる。周期境界条件にも対応しており、格子の端から反対側へつながるように処理する。

この方法によって、無関係な円盤同士の距離計算を減らしている。

## 4. FIREによる緩和

反発力を計算した後、円盤の位置を更新して重なりを解消する。

ここで使用しているのが **FIRE（Fast Inertial Relaxation Engine）** である。

FIREは、力に応じて粒子を移動させながら、速度と力の方向の関係を使って移動の仕方を調整する最適化手法である。

基本的な処理は次のとおり。

```text
現在の円盤配置
      ↓
反発力を計算
      ↓
仮想速度を更新
      ↓
速度と力の関係を確認
      ↓
時間刻み dt を調整
      ↓
円盤の位置を更新
      ↓
重なりが解消された？
  ├─ No → 繰り返す
  └─ Yes → 緩和終了
```

速度と力が同じ方向を向いているときは、時間刻みを大きくして効率を上げる。

逆に、進行方向が悪くなったときは速度をリセットし、時間刻みを小さくする。

これによって、単純な勾配降下法よりも効率的に安定配置へ到達することを狙っている。

## 5. MPIによるマルチスタート探索

今回の提出版で大きく重要なのが、複数の初期条件を並列探索する仕組みである。

同じ問題を異なる乱数で複数回探索し、良い初期配置を探す。

### 5.1 初期配置への摂動

初期面積分率は

```cpp
INITIAL_PHI = 0.75;
```

である。

各円盤には、直径に比例したランダム変位を加える。

\[
x_i'=x_i+0.10d_i r_{xi}
\]

\[
y_i'=y_i+0.10d_i r_{yi}
\]

ここで \(r_{xi},r_{yi}\) は \([-1,1)\) の乱数である。

乱数の種は問題番号・worker・試行番号から決定するため、同じ条件なら再現可能な探索になる。

### 5.2 2つのworkerによる並列探索

提出版ではMPIを利用し、同じ問題に対して2つのworkerを割り当てている。

```text
問題1
 ├─ Worker 0
 └─ Worker 1

問題2
 ├─ Worker 0
 └─ Worker 1

...

問題8
 ├─ Worker 0
 └─ Worker 1
```

つまり、8問それぞれに2プロセスを割り当てる構成を想定している。合計16 MPIプロセスである。

各workerは異なる乱数seedを使い、初期配置を変えながら複数回探索する。

1回の探索が終わるたびに、その配置を候補として保存し、各worker内で上位2つを保持する。

### 5.3 候補解の交換と選別

スクリーニングフェーズが終了すると、2つのworker間で候補配置をMPI通信によって交換する。

```text
Worker 0                    Worker 1
候補上位2つ                 候補上位2つ
     │                          │
     └──────── MPI交換 ─────────┘
                    ↓
             最大4候補を統合
                    ↓
                Lで整列
                    ↓
              それぞれ選択
```

ここでは

```cpp
V2_CLOSE_L = 5.0e-3;
```

が使われている。

最良候補と2番目の候補の \(L\) の差が十分大きければ、両workerが最良候補から再探索する。

差が小さければ、Worker 0は最良候補、Worker 1は2番目の候補を選ぶ。

これは、2つのworkerが似た探索を重複して行うのを避け、異なる局所解をさらに改善するための仕組みである。

## 6. 適応的圧縮とジャミング境界の二分探索

初期配置の緩和が終わると、箱を小さくして円盤を圧縮する。

ここでは面積分率 \(\phi\) を直接増やしていく。

初期圧縮幅は

```cpp
INITIAL_DPHI = 4.0e-3;
```

である。

成功すれば

```cpp
dphi *= 1.08;
```

として、次の圧縮幅を少し大きくする。

つまり、序盤は大きなステップで効率よく進む。

### 6.1 圧縮に失敗したら二分探索

圧縮幅が大きすぎてFIREでも重なりを解消できなくなった場合、その面積分率を失敗上限として保存する。

```text
φ = 0.8500 成功
φ = 0.8540 失敗
       ↓
φ = 0.8520 を試す
       ↓
成功なら下限を更新
失敗なら上限を更新
```

このように、成功する面積分率と失敗する面積分率の間を二分探索する。

これによって、現在の配置でどこまで圧縮できるかを効率的に調べる。

ジャミング境界の探索幅は

```cpp
V2_SCREEN_WIDTH = 5.0e-5;
```

である。

この幅まで狭くなった候補を、スクリーニング段階で完成と判断する。

## 7. 局所解からの脱出：膨張・振動・再圧縮

今回のアルゴリズムで特徴的な部分の一つである。

FIREは円盤の重なりを解消するのは得意だが、重なりがない状態で、さらに密な配置へ自発的に移動することはできない。

つまり、局所解にはまる可能性がある。

そこで、現実の粒状物質を振動させて詰まり方を変える操作を模倣している。

提出版では、`escape_local_minimum2()` を利用した、段階的なescape処理を実装している。

### 7.1 一時的に箱を膨張させる

通常のescape2では、

```cpp
ESCAPE2_EXPANSIONS[0] = 1.0e-2;
```

なので、箱を約1%膨張させる。

### 7.2 円盤にランダム変位を与える

```cpp
ESCAPE2_KICKS[0] = 2.5e-1;
```

つまり、各円盤の直径の約25%を基準とする大きさで、各方向にランダム変位を与える。

ただし、全円盤が同じ方向へ移動する成分は平均値を引いて除去する。

周期境界条件では、一様な平行移動をしても相対配置が変化しないためである。

### 7.3 膨張した状態でFIRE

円盤同士に少し自由度を与えた状態でFIREを行い、重なりを解消する。

### 7.4 段階的に再圧縮

一気に元の箱の大きさに戻すのではなく、4段階で元の \(L\) まで戻す。

```text
膨張した状態
     ↓
少し圧縮 → FIRE
     ↓
さらに圧縮 → FIRE
     ↓
さらに圧縮 → FIRE
     ↓
元のL → FIRE + 制約検証
```

この処理によって、振動で生じた新しい配置を徐々に安定させる。

### 7.5 新しい配置で再圧縮できるか試す

元の \(L\) に戻っただけでは、局所解脱出が成功したとは判断しない。

さらに小さな圧縮を2回試し、非重複・移動距離の条件を満たしながら、以前より高い面積分率に到達できた場合のみ成功とする。

**振動によって配置が変わっただけでは不十分で、実際に以前より圧縮できたことを成功条件にしている。**

escape2の最大試行時間は約25秒で、膨張・再圧縮・圧縮プローブにそれぞれ時間枠を設けている。

なお、通常のrefine経路で使用するのは `ESCAPE2_EXPANSIONS[0]` と `ESCAPE2_KICKS[0]`、つまり1%膨張・25%摂動である。2%、4%などの設定値もあるが、通常経路ではそれらを順番に試す設計にはなっていない。

## 8. 最終精度を上げるRefinementフェーズ

並列スクリーニングで良い候補を見つけた後は、各workerが選択した候補をさらに改善する。

ここでは次の機構を組み合わせる。

- 適応的圧縮
- 二分探索
- FIREの再試行
- 条件付きの局所解脱出

圧縮試行が失敗した場合、最初のFIRE設定で一度試した後、ジャミングらしい失敗であれば `Retry` 設定でもう一度試す仕組みがある。

これによって、最初のFIRE設定では収束しなかっただけの試行を、不必要に失敗扱いすることを避けている。

### 8.1 実行時間の配分

```text
0〜550秒
  Screening
  複数seedによる初期配置探索
  各workerで上位候補を保持
        ↓
550〜595秒
  Refinement
  MPIで候補を交換
  選別した候補をさらに圧縮
        ↓
最終出力
```

特に終盤8秒では、次の圧縮試行に必要な時間を予測する。

予測時間が残り時間を超える場合は、圧縮幅を半分にするなどして調整する。それでも間に合わない場合は、新しい試行を開始しない。

これにより、最後の試行が時間切れになって出力できなくなるリスクを抑えている。

---

## 9. 最後の候補選択と出力

Refinementを終えた2つのworkerは、最終候補を再びMPIで交換する。

それぞれ独立して、

- 最大重なり
- 平均移動距離

を確認し、有効な候補のうち \(L\) が小さいものを選ぶ。

そして、Worker 0だけが `sc26_output()` を呼び出して最終解を出力する。

また、コードには5秒間隔で配置を記録する `v2_movie_frame()` がある。

これはWorker 0だけが `sc26_output()` を使って途中経過を追記する仕組みである。最終的な選択解も最後に追記される。

## 10. 提出版の仕様まとめ

これまでの開発段階のコードと比べると、提出版では次のようになっている。

| 項目 | 提出版での実際の仕様 |
|---|---|
| 初期面積分率 | 0.75 |
| 初期摂動 | 直径の10%を基準とするランダム変位 |
| 初期条件の探索 | 各問題につき2 workerでマルチスタート |
| 初期配置の候補数 | 各workerで上位2候補を保持 |
| 圧縮 | 適応圧縮 + 二分探索 |
| 局所解脱出 | escape2（膨張・振動・段階的再圧縮・改善確認） |
| FIRE | 通常の圧縮では基本設定、Retryやescapeでは別設定 |
| 終盤 | 時間予測に基づく圧縮試行制御 |
| 最終選択 | MPIで候補を交換し、最小の有効な \(L\) を選択 |

### 初期摂動に関する変更

以前検討していた `PERTURBATION_AMPLITUDE[8]` による摂動振幅の比較実験は、提出版では採用していない。

代わりに、問題番号とworker・試行番号ごとに異なるseedを設定し、一定の初期摂動量で複数探索する方式になっている。

また、ファイル前半には過去の実装を残した旧 `main` があるが、`#define main sc26_legacy_main_v2` と `#undef main` によって別名になっている。

**実際にプログラムのエントリーポイントとして実行されるのは、MPIを初期化するファイル末尾の `main` である。**

したがって、旧 `main` にある `baseline` や `phased` などのモード選択が、そのまま提出版の実行設定になっているわけではない。

## 11. 解法の本質

今回の提出版を、最適化の観点から整理すると次のようになる。

| 技術 | 解決しようとしている課題 |
|---|---|
| Cell List | 円盤間の距離計算が多すぎる |
| OpenMP | 1つの探索の計算時間が長い |
| FIRE | 円盤の重なりを効率よく解消したい |
| マルチスタート | 初期条件による局所解の違いを利用したい |
| 候補解の交換 | 複数探索から有望な解を選びたい |
| 適応圧縮 | 序盤の探索を高速化したい |
| 二分探索 | ジャミング境界を精密に調べたい |
| 振動による脱出 | 局所解から抜け出したい |
| Refinement | 有望な解をさらに改善したい |
| 時間予測制御 | 制限時間内に確実に出力したい |

特に重要なのは、これらを単純に組み合わせたのではなく、**探索の段階に応じて役割を変えていること**である。

```text
異なる初期配置を大量に探索
          ↓
有望な配置を選ぶ
          ↓
大きな刻みで圧縮
          ↓
ジャミ
