# SuperCon参加記

本校として初めてSuperCon本戦に出場しました。壮行会で激励を受けて臨みましたが、残念ながら良い結果を残すことはできませんでした。それでも、とても貴重な経験になりました。この記事では、参加を通じて得た経験を紹介します。

## SuperConとは

SuperConは、高校生や高専生を対象とした「[Supercomputing Programming Contest（SuperCon）](https://www.supercon.cii.isct.ac.jp/attwiki/index.php )」です。「夏の電脳甲子園」とも呼ばれています。1995年に始まり、2〜3人のチームで、最先端の科学技術に関する難問を解くプログラムを作成し、その実行速度と正確さを競います（[大会規則](https://www.supercon.cii.isct.ac.jp/attwiki/?plugin=attach&refer=SupercomputingContest2026&openfile=kisoku2026.pdf )）。

本戦は4日間にわたって行われ、2026年はスーパーコンピュータ「[富岳](https://www.r-ccs.riken.jp/fugaku/ )」が使用されました。

[情報オリンピック（JOI）](https://www.ioi-jp.org/ )や[パソコン甲子園（PCK）](https://pckoshien.u-aizu.ac.jp/ )と並ぶ、高校生が出場できる代表的なプログラミング系大会の一つです。個人的には、AIの利用に関する制限がない点も、SuperConの特徴だと感じています。

## 予選

### 問題概要

- 優先順位付投票制（[問題本文](https://www.supercon.cii.isct.ac.jp/attwiki/index.php?plugin=attach&refer=SupercomputingContest2026&openfile=SuperCon2026Yosen.pdf )）

有権者が候補者に順位をつけて投票し、得票数が最も少ない候補者を順に除外して当選者を決める、優先順位付投票制をシミュレートする問題です。

さらに、有権者の順位が変更されたり、候補者が立候補を辞退したりするクエリが与えられます。それらを順番に処理し、候補者の除外順と当選者を求めます。得票数が同じ候補者が複数いる場合は、番号が最も大きい候補者を除外します。

### 解法

前処理では、有権者ごとに各候補者より上位に置かれた候補者の集合を求め、それを候補者ごとに集計します。さらにSOS DPを使い、候補者の残り方ごとに各候補者が獲得する票数を計算しておきます。

順位変更時は、その有権者の旧順位による票数を該当する集合から引き、新順位による票数を加えます。この処理は `O(2^M)` です。

立候補辞退のクエリでは、辞退者を除いた候補者集合から始め、保存済みの得票数を参照して、最少得票（同数なら番号最大）の候補者を順に除外します。最後に残った候補者を当選者とします。この処理は `O(M^2)` です。

### 感想

AtCoder Beginner Contest（ABC）にも参加したことがなかった僕にとっては、難易度の高い問題でした。

最初は自力で解こうとしました。クエリの意味を調べて理解し、候補者の残り方ごとに得票数を前計算する方法を考えましたが、どのような状態をどのように集計すればよいのか分からず、行き詰まりました。

そこで、Webブラウザー上のChatGPTに解法を相談し、Codexを使って実装しました。

最初の実装では、候補者の集合ごとに、全有権者の票を「その集合内で最も順位の高い候補者」に割り当てて集計していました。SuperCon 2級認定問題では候補者数が `1 <= M <= 4` と少なく、この方法でも処理できました。しかし、予選では `1 <= M <= 13` となり、候補者の集合ごとに全有権者の票を集計する方法では、処理が間に合いませんでした。

そこで改めてChatGPTに相談し、SOS DPを使って得票数を効率よく集計する方法にたどり着きました。

### 問題概要

- できる限り小さい正方形トーラスに3000個の円を敷き詰めよう（[問題本文](https://www.supercon.cii.isct.ac.jp/attwiki/index.php?plugin=attach&refer=SupercomputingContest2026&openfile=SuperCon2026_final_problem.pdf )）
- [問題解説](https://www.supercon.cii.isct.ac.jp/attwiki/index.php?plugin=attach&refer=SupercomputingContest2026&openfile=SuperCon2026_final_kaisetsu.pdf )

半径と初期位置がそれぞれ異なる3000個の円を、正方形トーラスの中にできるだけ密に配置する問題です。

円は初期位置からの移動距離に制約があるため、自由に並べ替えることはできません。一方で、半径の近い円を入れ替えるなど、現実の物理的な移動とは異なる操作も可能です。限られた条件の中で円の配置を工夫し、密度を高めることが鍵となります。

### 解法

- [提出プログラムの解法解説](report.html?file=SuperCon2026%20提出プログラムの解法解説.md)

このプログラムは、円盤同士が重ならないよう配置を調整しながら、領域を少しずつ縮めていく解法です。円盤の移動にはFIRE法を使い、近くにある円盤だけを調べることで計算を効率化します。

複数のworkerが異なる初期配置から並列に探索し、見つかった良い配置を共有します。圧縮に失敗したときは縮める幅を小さくし、探索が停滞したときは円盤を少し動かしてから再挑戦します。最後に、制約を満たす配置の中から、領域の一辺 `L` が最も小さいものを選びます。



### 感想

#### 競技について

一般的な競技プログラミングではあまり見かけない問題に取り組み、解法を考え、他チームとの差の付け方を探る過程が新鮮でした。単純に圧縮するだけでは悪い局所解に陥ると気づき、初期条件を変えて何度も試す多スタート探索を導入したところ、より良い解を得られたことが印象に残っています。

また、チームメイトの結果やDiscordでの議論を通じて、他チームの方針や得点傾向について考えることができました。OpenMPとMPIを実際に比較し、処理の性質に応じて並列化手法を選ぶ大切さも学びました。チーム内で方針や進捗を共有できたことも、モチベーションの維持につながりました。

#### レポート提出

4日目には、コードに加えてレポートも提出しました。コードの提出後、昼食を含めて2時間ほどでレポートを仕上げる必要があり、慌ただしい作業となりました。

レポートは提示された設問に答える形式で、PDFでの提出が求められていました。しかし、MarkdownからPDFへの変換に慣れておらず、PDFの提出が締切を少し過ぎてしまいました。未提出にするよりはよいと考え、まずはMarkdown形式のファイルを締切までに提出しました。

#### 閉会式

夏休み明けのある日、午前の授業が終わった後、学校からZoomで閉会式に参加し、結果発表を見ました。

課題の監修を務めた教授が、「AIを使っているとはいえ、非常に優秀な成果を出している。皆さんと一緒に研究したい」という趣旨の話をしていたのが印象的でした。

課題解説のスライドでは、チーム名を伏せたうえで、各問題の上位チームの面積分率が発表されました。結果を見て、私たちは愕然としました。私たちの記録とは大きな差があったからです。点数がつく5位以内に、少なくとも一つは入っていることを願っていましたが、5位の記録も私たちの最終結果を大きく上回っていました。

そんな中、特に衝撃的な出来事がありました。課題解説が続く中、sabotageのメンバーがDiscordで「自分たちのチームは、発表されている1位の面積分率を大きく上回っている」と発言しました。採点に使われる判定プログラムの処理が簡略化されている点を利用し、円が重なっていても判定を通過する配置を作ったと説明していました。

順位発表では、案の定、私たちのチームが呼ばれることはありませんでした。一方、sabotageは特別賞を受賞しました。優勝には至らなかったものの、失格とはならず、賞を受けられて本当によかったと思いました。

#### 反省

上位チームの話を聞き、気づいたことがあります。この競技では、プログラミングの技術だけでなく、情報収集や分析も重要です。

- 入力生成プログラムの意図的な傾向に気づき、それを解法に取り入れたチーム
- 採点に使われる判定プログラムの仕様上の隙に気づき、それを活用して高い成績を出したチーム
- 今回の課題とよく似た問題を扱う専門的な論文を見つけ、優勝したチーム

初めて知る知識でも、生成AIに読ませれば、それを活用した実装を作ることができます。試行錯誤をするうえで、幅広い知識を持ち、選択肢を増やしておくことは大切です。しかし、それは有望な解法を探るための手段であり、最も大切なのは、解法に関する情報を得ることだと感じました。

大会規則には、「チーム間で意見やアイデアを交換することは、大会の趣旨からしても、好ましいことである」と記されています。しかし、情報戦であることを参加者が理解していたからか、大会全体のDiscordでは雑談などを通じて盛んに交流が行われていましたが、解答プログラムの提出締切までは、具体的な解法に関する発言は見られませんでした。

来年度も参加できたら、特に関心や課題が近いチームに、1対1での情報交換を提案してみるのもよいかもしれません。
また、情報戦で勝つために、AIエージェントを利用した論文検索や、課題の詳細な分析を行っていきたいです。
